# 프로젝트 R — M0 관문 판정 시트

개발 체크리스트 v1.2 · 3장 기준
Version 1.0 · 2026.08.29

---

## 이 문서 사용법

M0 관문의 Q1·Q2·Q3·Q4를 실제로 돌리기 위한 작업지다. **한 번 쓰고 버린다.**

- 무엇을 만드는지는 기획서, 무엇을 어디까지 만들었는지는 개발 체크리스트를 본다.
- **판정 결과는 이 문서가 아니라 `프로젝트R_개발진행기록.md` 14장에 적는다.**
  여기에만 적으면 시트를 버릴 때 판정도 같이 사라진다.
- 빈칸을 채우는 순서는 1장 → 2장 → 3장 → 4장이다. **4장(외부 테스트)을 먼저 하면 안 된다.**
  성능이 실패면 테스터가 프레임 저하를 공포로 착각한다.

관문 통과 조건은 체크리스트 3.5절에 있다. 넷이 전부 통과여야 하고, **경계는 조치를 마치고
재측정해 통과로 바꾼 뒤에 센다.**

## 1. 사전 준비

측정을 시작하기 전에 이 다섯 개를 확인한다. 하나라도 빠지면 측정치가 못 쓰게 된다.

```

                                 08-26 빌드에는 3종만 있고 값도 전부 같다
□ 라이트맵 살아 있는지 확인        ProjectR.exe -projectr-verify
```

## 2. Q1 성능 — 실기 측정

**개발 PC로 재면 안 된다.** GTX 1650급 실기에서 1080p로 잰다.

### 2.1 최악 구간은 넓은 홀이 아니라 긴 복도다

체크리스트 v0.1은 넓은 홀을 최악으로 상정했는데, 진행기록 5.4절 측정에서 뒤집혔다.
홀이 복도보다 가벼웠다. **실기 측정도 복도에서 한다.**

개발 PC 에디터 기준 참고값 (진행기록 5.6절):

| 구간 | GPU | CPU | 배치 |
|---|---|---|---|
| 복도 | 0.80ms | 6.05ms | 14 |
| 홀 | 0.31ms | — | 6 |

### 2.2 측정 지점 셋

같은 시드로 세 자리를 잰다. 시드는 `map.seed`로 확인해 아래에 적어 둔다.

**측정 시드: ____________**

각 자리에서 **30초 이상** 머무르며 평균·최소·최대를 읽는다. 순간값 하나로 판정하지 않는다.

```
① 긴 복도 · 손전등 켠 상태 · 깜빡이는 등이 보이는 자리
   가는 법: 복도 구간을 찾아 걸어간다. player.flashlight 로 손전등을 켜 둔다
   평균 ______ fps   최소 ______ fps   최대 ______ fps   메모리 ______ MB

② 몬스터 추격 중
   가는 법: monster.spawn 10 으로 가까이 불러내고 발각된 뒤 복도를 달린다
   평균 ______ fps   최소 ______ fps   최대 ______ fps   메모리 ______ MB

③ 넓은 홀 (대조군)
   ①이 홀보다 나쁘다는 5.4절 결과가 실기에서도 같은지 확인하는 용도다
   평균 ______ fps   최소 ______ fps   최대 ______ fps   메모리 ______ MB
```

### 2.3 판정

| 판정 | 조건 | 조치 |
|---|---|---|
| **통과** | 세 자리 모두 평균 60fps 이상이고 최소값이 크게 파이지 않는다 | 없음 |
| **경계** | 60fps에 못 미치지만 55fps 이상 | 프리팹 수 감소 또는 오클루전 컬링 강화 후 **재측정**. 통과로 바뀌어야 센다 |
| **실패** | 55fps 미만이거나 최소값이 반복해서 크게 파인다 | 생성 방식 전환 — 1순위 WFC · 2순위 BSP+순환로 · 3순위 방 이어붙이기 |

**Q1 판정: □ 통과   □ 경계   □ 실패**

## 3. Q1 부속 — 메모리와 저장 파일

### 3.1 30분 연속 플레이 메모리

맵 재생성은 500회에서 +3.6MB로 확인이 끝났다(진행기록 5.8절).
**아직 안 본 것은 걸어 다니는 동안 생기는 증가다** — 이동·오디오·몬스터가 그 뒤에 생겼다.

```
□ 30분 연속 플레이. 도중에 나가지 않는다
   시작 ______ MB   10분 ______ MB   20분 ______ MB   30분 ______ MB
   증가가 평탄해지는가 □ 예  □ 아니오(선형으로 계속 늘면 누수다)
```

선형으로 계속 늘면 할당자 여유분이 아니라 진짜 누수다. 5.8절의 정적 배칭 메시가 그 예였다.

### 3.2 저장 파일 호환

빌드의 `persistentDataPath`는 에디터와 다르다. 그래서 빌드에서만 드러나는 자리다.

```
□ 저장 파일이 없는 상태에서 처음 실행 → 새 진행으로 시작하는가        □ 예  □ 아니오
□ 백룸 진입 → 방송 시간이 240에서 180으로 줄었는가                   □ 예  □ 아니오
□ 탐험 도중 강제 종료 → 다시 켜면 가방만 비고 시간은 180 그대로인가   □ 예  □ 아니오
□ 하루 마감 후 재실행 → 날짜와 후원금이 그대로인가                    □ 예  □ 아니오
```

세 번째가 핵심이다. 방송 시간까지 되돌아가면 위기 회피 수단이 된다(기획서 11.1절).

## 4. 외부 테스트 — Q2 · Q3 · Q4

세 질문의 답이 같은 자리에서 나오므로 한 번에 부른다.

```
□ 테스터 3~5명 확보. 개발자가 아닌 사람이어야 한다
```

### 4.1 순서 — Q2를 먼저 본다

**Q2 하나만 성격이 다르다.** 나머지 셋은 실패해도 그 시스템만 고치면 되지만,
Q2가 실패하면 그 위에 쌓은 Phase 3·4 작업물이 재설계에 함께 휩쓸린다.

몬스터 없는 빌드를 따로 만들 필요는 없다. 같은 빌드에서 `monster.freeze 1`로 멈춰 두고
앞부분을 관찰한 뒤, 풀고 나머지를 본다.

```
1. monster.freeze 1  →  Q2 관찰 (혼자 걷는 백룸이 무서운가)
2. monster.freeze 0  →  Q3 관찰 (추격과 도주)
3. 탈출까지 한 바퀴  →  Q4 관찰 (수집과 정산)
4. 마무리 질문
```

### 4.2 테스터에게 하는 말 — 이것만 말한다

> "설명은 안 할게요. 하고 싶은 대로 해 보세요. 소리 내서 생각하셔도 됩니다."

**조작을 알려주지 않는다.** 튜토리얼 없이 조작이 전달되는지는 M4에서 볼 항목이지만,
지금 알려주면 "길을 잃는 것이 긴장인가 짜증인가"의 답이 오염된다.
정말 못 하고 있으면 3분쯤 두고 본 뒤 최소한만 알려주고, **무엇을 알려줬는지 아래에 적는다.**

알려준 것: ________________________________________________

## 5. Q2 관찰 시트 — 공포

**질문: 몬스터 없이도 백룸이 무서운가.**

관찰자는 말을 걸지 않는다. 보이는 것만 적는다.

```
□ 몇 분에 지루해하는가                  ______ 분
□ 뒤를 돌아보는가                       □ 자주  □ 가끔  □ 안 함
□ 소리에 반응하는가                     □ 예  □ 아니오
   (어떤 소리에?  ______________________________ )
□ 길 잃음이 긴장인가 짜증인가            □ 긴장  □ 짜증  □ 둘 다
□ 전등 고장과 어두운 구역을 알아채는가    □ 예  □ 아니오
   랜드마크를 뺐으므로 이쪽이 그 역할이다
□ 걸음이 느려지는 순간이 있는가          □ 예(언제: ____________)  □ 아니오
```

### 판정

| 판정 | 조건 | 조치 |
|---|---|---|
| **통과** | 뒤를 돌아보고, 소리에 반응하고, 길 잃음을 긴장으로 받는다 | 없음 |
| **경계** | 반응은 있는데 약하다 | 사운드와 표식 보강 후 **재테스트** |
| **실패** | 지루해하거나 길 잃음을 짜증으로만 받는다 | 아트 방향·공간 규모·사운드 전면 재설계. **몬스터를 넣어도 해결되지 않는다** |

**Q2 판정: □ 통과   □ 경계   □ 실패**

**실패면 여기서 멈춘다.** M1을 시작하지 않고 백룸 공간 설계로 돌아간다(체크리스트 3.5절).

## 6. Q3 관찰 시트 — 실력감

**질문: 도망치는 것이 내 실력처럼 느껴지는가.**

```
□ 도망쳐 살아남았을 때 내가 잘했다고 느끼는가    □ 예  □ 아니오
   (테스터의 말 그대로:  ______________________________ )
□ 죽었을 때 운이 나빴다인가 내가 실수했다인가    □ 실수했다  □ 운이 나빴다  □ 모르겠다
□ 추격이 시작된 것을 소리로 알아채는가           □ 예  □ 아니오
□ 매복의 정적이 읽히는가                        □ 예  □ 아니오
□ 앉기가 몸을 숨겨 준다는 것을 스스로 찾는가      □ 예  □ 아니오
□ 어둠 속에서 몬스터가 보이는가                  □ 예  □ 아니오
□ 순환로로 돌아 나가는 것을 쓰는가               □ 예  □ 아니오
□ 막다른 길에서 죽는가                          □ 예(몇 번: ___)  □ 아니오
```

### 판정

| 판정 | 조건 | 조치 |
|---|---|---|
| **통과** | 살아남으면 잘했다고 느끼고, 죽으면 내 실수라고 말한다 | 없음 |
| **경계** | "모르겠다"가 섞인다 | 소리로 정보를 더 노출한 뒤 **재테스트** |
| **실패** | 막다른 길에서 죽거나 무슨 일인지 모르겠다고 한다 | 막다른 길이면 순환로 보정 강화. 모르겠다면 소리 설계 재작업 |

**Q3 판정: □ 통과   □ 경계   □ 실패**

## 7. Q4 관찰 시트 — 수집

**질문: 줍고 정리하고 들고 나오는 것이 재미있는가.**

이상물체가 6종이 되었으므로(진행기록 13.2절) 이번에 처음으로 제대로 물어볼 수 있는 항목이다.
2x3 먹통 송출 장비가 특별 하나뿐이고 칸당 값이 가장 높다. **그것을 주웠을 때를 특히 본다.**

```
□ 좋은 물건을 주웠을 때 기쁜가                  □ 예  □ 아니오
   (어떤 물건에서?  ______________________________ )
□ 무엇을 버릴지 고민이 생기는가                  □ 예  □ 아니오
   (무엇과 무엇 사이에서?  ______________________ )
□ 격자를 정리하는 행동을 하는가 (끌기 · R 회전)   □ 예  □ 아니오
□ 가방 24칸이 적당한가                          □ 좁다  □ 적당  □ 넓다
□ 격자가 우하단에 있는 것이 맞는가               □ 예  □ 아니오
   아바타 자리와 겹치므로 M1에서 함께 정한다
□ "한 개만 더"와 "지금 나가자"가 충돌하는가       □ 예  □ 아니오
□ 정산 화면이 보상으로 느껴지는가                □ 예  □ 아니오
□ 전부 잃었을 때 다시 하겠다인가 그만두겠다인가    □ 다시  □ 그만
```

### 타이머가 없는 자리를 따로 본다

백룸 안의 제한 시간을 없앴으므로(진행기록 10.9절) v0.1에 있던
"타이머가 실제로 결정을 바꾸는가"를 물어볼 자리가 비었다.
**지금 나가고 싶게 만드는 것은 몬스터와 손전등 배터리 둘뿐이고, 그것으로 충분한지는 아직 모른다.**
이번 변경에서 가장 크게 감수한 위험이므로 따로 본다.

```
□ 타이머 없이도 나가고 싶어지는가                □ 예  □ 아니오
   (무엇 때문에?  □ 몬스터  □ 배터리  □ 가방이 참  □ 그냥 지겨워서 )
□ 배터리를 신경 쓰는가                          □ 예  □ 아니오
□ 언제 나가기로 결정했는가                       ______________________________
```

"그냥 지겨워서"가 나오면 그것은 나가고 싶은 것이 아니라 그만두고 싶은 것이다. 구분해서 적는다.

### 판정

| 판정 | 조건 | 조치 |
|---|---|---|
| **통과** | 좋은 물건에 기뻐하고, 버릴 것을 고민하고, 전부 잃고도 다시 하겠다고 한다 | 없음 |
| **경계** | 고민이 약하거나 정산이 밋밋하다 | 인벤토리 격자 규칙 또는 보상 곡선 조정 후 **재테스트** |
| **실패** | 전부 잃고 그만두겠다고 한다 | 손실 규칙 완화. `ILossPolicy` 구현체 교체로 끝난다 |

**Q4 판정: □ 통과   □ 경계   □ 실패**

### 손실 완화 순서

실패했을 때만 쓴다. **위에서부터 하나씩만 적용하고 다시 본다.** 한꺼번에 넣으면 무엇이 들었는지 모른다.

```
□ 1단계: 방송 사고 클립 보상 — 이상물체만 지우고 후원금은 일부 남기는 구현체
□ 2단계: 회수 기회 — 기절 지점을 결과 표식에 남기는 구현체
□ 3단계: 보험 업그레이드 — 보유 업그레이드를 보고 남길 양을 정하는 구현체
□ 4단계: 일부 소실 — 가방 절반 또는 고가품 우선으로 지우는 구현체
```

### 등장 확률이 균등하다는 것을 알고 본다

`BackroomsAnomalyPlacer`가 데이터베이스에서 균등 추첨하므로 2x3 특별이 흔함과 같은 빈도로 나온다.
**"좋은 물건을 주웠을 때 기쁜가"가 미달이면 원인 후보 1번이 이것이다**(진행기록 13.3절).
한 판에 특별이 몇 개 나왔는지 세어 둔다.

## 부록. 디버그 명령

`SWDebugConsole`에 등록되어 있다.

| 명령 | 쓰는 자리 |
|---|---|
| `state.print` · `state.reset` · `state.nextday` | 1장 사전 준비, 3.2절 저장 확인 |
| `backrooms.enter` · `backrooms.exit` | 반복 진입 |
| `map.seed` | 2.2절 측정 시드 기록 |
| `map.regenerate` · `map.soak <횟수>` | 재생성 메모리 (이미 확인 완료) |
| `player.flashlight` · `player.battery` | 2.2절 ①, 7장 배터리 관찰 |
| `player.teleport` | 측정 지점으로 이동 |
| `monster.spawn <거리>` | 2.2절 ② 추격 측정 |
| `monster.freeze <0\|1>` | 4.1절 Q2를 먼저 보기 위해 멈춘다 |
| `backpack.print` | 7장 가방 상태 확인 |
| `view.ceiling` · `view.bright` · `view.maze` | **측정 중에는 쓰지 않는다** |

빌드 실행 파일 명령줄 인자:

| 인자 | 하는 일 |
|---|---|
| `-projectr-verify` | 라이트맵 확인 후 종료 코드로 알린다. 1장에서 쓴다 |
| `-projectr-screenshot <경로>` | 화면을 저장한다 |
| `-projectr-soak <횟수>` | 맵 재생성을 반복한다 |
